## What is Iwan?

Iwan is an AI-powered Slack bot that acts as a team member. Mention `@Iwan` with a question — it searches your Slack history, Notion knowledge base, and Workforce Planner, then answers using Claude AI with full context.

**Example:**
> **You:** `@Iwan who is available in March?`
>
> **Iwan:** Based on Workforce Planner data, people available in March:
> - Alex Johnson (Backend) — 0%
> - Maria Torres (PM) — 0%
> - Sophie Lee (UX/UI Designer) — 0%
> ...

## Why Iwan?

| Problem | How Iwan helps |
|---------|---------------|
| "Who's available for a new project?" | Queries Workforce Planner and lists people with low utilization |

## Key Features

**Context-Aware AI** — combines data from 3 sources before answering

**Slack Crawler** — indexes messages for full-text search across channels

**Smart Routing** — automatically detects which data source is relevant to your question

**Proactive Alerts** — daily overbooking and low utilization warnings

**Weekly Summary** — Monday morning team allocation report, generated by AI

**Thread Memory** — remembers conversation context within Slack threads

## Integrations

### Slack _(core)_

Connects via Socket Mode — no public URL needed. Crawls messages from all channels it's invited to, responds to `@Iwan` mentions in threads, and posts proactive alerts.

### Notion

Searches your team's knowledge base for relevant pages. Extracts keywords from questions (with stop-word removal), fetches page content including tables and nested blocks, and passes up to 3 pages as context to Claude.

**Example:** `@Iwan what are the delivery team KPIs?` → finds KPI page in Notion → Claude answers

### Workforce Planner

Read-only integration with Workforce Planner (FastAPI + PostgreSQL). Supports JWT authentication with auto-refresh, timeline queries with natural language date parsing, and compact context formatting for Claude.

**Example:** `@Iwan team backend` → fetches Backend team allocations → Claude formats a detailed breakdown

<details>
<summary><strong>Proactive Alerts</strong> — daily overbooking detection</summary>

When `WP_ALERT_CHANNEL` is configured, Iwan checks the timeline daily and posts alerts for:
- **Overbooking** — utilization > 100%
- **Low utilization** — utilization < 20% (configurable)

Alerts are deduplicated to avoid spam.
</details>

<details>
<summary><strong>Weekly Summary</strong> — Monday morning team report</summary>

When `WP_SUMMARY_CHANNEL` is configured, every Monday morning Iwan posts:
- Overall company utilization
- Per-team breakdown
- People on bench (0%)
- Overbooked employees
- Ending and new assignments this week

The summary is generated by Claude based on raw Workforce data.
</details>

## Architecture

```
User @Iwan
    │
    ├── Validate message
    ├── Check rate limit (10/min per user)
    ├── Classify (spam detection via Claude Haiku)
    │
    ├── Search Slack history ──────┐
    ├── Search Notion pages ───────┼── parallel
    ├── Search Workforce Planner ──┘
    │
    ├── Get conversation history (Supabase)
    ├── Call Claude Sonnet with combined context
    ├── Save to conversation memory
    │
    └── Format & send response in thread
```

## Getting Started

### Prerequisites

- **Node.js 20.x**
- **Slack workspace** with Bot Token + App Token (Socket Mode enabled)
- **Supabase** project (PostgreSQL + full-text search)
- **Anthropic API key** (Claude)
- _(optional)_ Notion integration token
- _(optional)_ Workforce Planner instance

### Quick Start

```bash
# Clone
git clone https://github.com/Iwan1212/iwan.git
cd iwan

# Install
npm install

# Configure
cp .env.example .env
# Edit .env with your credentials

# Test
npm test

# Run
npm start
```

## Contributing

Contributions are welcome! Whether it's a bug fix, new feature, or documentation improvement — we'd love your help.

### How to Contribute

1. **Fork** the repo and clone it locally
2. **Create a branch:** `git checkout -b feat/my-feature`
3. **Write code** following the guidelines below
4. **Add tests** for any new functionality
5. **Run `npm test`** — all 109+ tests must pass
6. **Open a Pull Request** with a clear description

### Coding Guidelines

| Rule | Example |
|------|---------|
| One function = one task | `searchWorkforce()` only searches, doesn't format |
| Max 30 lines per function | Split if longer |
| Comments in Polish above functions | `// Pobierz timeline alokacji` |
| English variable names | `const employees = ...` |
| Graceful degradation | Return `[]` or `null` on error, never throw |
| Plain JavaScript only | No TypeScript — Node.js 20 |

### Test Conventions

- Mirror the patterns in `tests/notion.test.js` or `tests/workforce.test.js`
- Mock all external dependencies (`jest.mock(...)`)
- Test happy path **and** error cases
- Descriptive test names

### Good First Issues

New to the project? Here are some ideas:

- **Add English command aliases** — currently all commands are in Polish (`/iwan szukaj`, `/iwan kto-wolny`). Add English versions (`/iwan search`, `/iwan who-free`) — see [v0.6 roadmap](#v06--english-commands--enhanced-workforce)
- Add a new slash command
- Improve Claude context formatting
- Add support for a new Workforce Planner endpoint
- Better user-facing error messages
- Increase test coverage
